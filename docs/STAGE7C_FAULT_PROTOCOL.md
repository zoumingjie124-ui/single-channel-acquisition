## 2. 新增协议帧

### 2.1 FAULT (0x86) — 9 字节

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | `t_ms` | u32 | 事件时刻 |
| 4 | `event` | u8 | **1 = 确认，2 = 恢复** |
| 5 | `fault_id` | u8 | 故障种类；0 保留 |
| 6 | `active` | u8 | 上报**之后**仍处于已确认态的位掩码 |
| 7 | `value` | u16 | 观测量；`STUCK` = 最近结算块的 span（mV） |

- 只在**跃变**时发：确认一次、恢复一次，ACTIVE 期间不重复（500 次连续调用零上报，有用例）；
- `active` 用掩码而非单值：多故障并存时恢复只清自己那一位，其余位原样带出；
- 帧头 SEQ 仍走设备全局帧序号，**不破坏**现有序号连续性统计。

契约向量（`fw_tests/test_fault.c` 与 `host/tests/test_fault_joint.py` 共用同一串字节）：

```
确认：AA 55 86 09 00 B8 0B 00 00 01 01 01 0C 00 F9 45
恢复：AA 55 86 09 01 70 17 00 00 02 01 00 78 00 54 D2
```

### 2.2 SET_DIAG (0x15) — 1 字节

| 偏移 | 字段 | 取值 |
|---|---|---|
| 0 | `enable` | 0 = 关闭，1 = 使能 |

**应答规则**：`LEN ≠ 1` 或 `enable > 1` → ACK `result=1`（参数错误），**不进回调**；
合法 → 调 `ctx_set_diag()`，成功后 ACK `result=0`。
**ACK 在配置生效之后发出**，所以"收到 OK"就代表已经切好。
关闭诊断不清故障掩码——一个真实存在的故障不该因为关了诊断就消失。

### 3.2 类 B：软件模拟（跑在 PC 上，构造数据）

- `gui_smoke.py` 往界面里喂合成的 FAULT 确认/恢复帧，断言标签从"无"变"STUCK 卡死"再变回"无"；

### 3.3 类 C：真实板卡（烧录 + 运行，输入是真实电位器）

固件 `Code=22204`，COM6，115200，上电后输入 942 mV 静置。

| # | 动作 | 结果 | 判定 |
|---|---|---|---|
| 1 | 诊断未使能，观察 3 s | **FAULT 0 帧** | ✅ 默认关闭不误报 |
| 2 | `SET_DIAG(1)` | ACK `result=OK` | ✅ |
| 3 | 保持输入不动 | **约 3.0 s 后 1 帧 FAULT 确认**，`value=9 mV`、`mask=0x01` | ✅ 与 3 块×1 s 设计一致 |
| 4 | `stat` | `DIAG en=1 state=2 conf=1 span=9 unev=0 mask=1` | ✅ 内部状态与帧一致 |
| 5 | `SET_DIAG(2)` | ACK `result=1`（参数错误），`en` 仍为 1 | ✅ 非法值进不到回调 |
| 6 | `SET_DIAG` 且 `LEN=2` | ACK `result=1` | ✅ |
| 7 | `SET_DIAG(0)` | ACK OK，**期间 0 帧 FAULT**，`state=2 mask=1` 保留 | ✅ 关闭不产生"假恢复" |
| 8 | 再 `SET_DIAG(1)` | 3.5 s 内 **0 帧** | ✅ 故障没消失，不重复确认 |
| 9 | **人缓慢拧电位器来回**（真实电气变化） | `span=187 mV` → **FAULT 恢复，mask=0x00** | ✅ 恢复路径打通 |
| 10 | 手离开、输入重新静置 | `span=8 mV` → **FAULT 再次确认**，`conf=2` | ✅ 重复触发 |

全程 `drops=0 / adc_err=0 / uart_err=0 / frame_err=0 / 解析错误=0`；
拧动期间 `chg`（告警切换）从 0 涨到 4，说明**告警链路在诊断开启时仍然正常工作**。
原始记录：`docs/STAGE7C_BOARD_RAW.txt`。

> **类 C 与类 D 的界线**：这里的"卡死"是"电位器没动"，不是"传感器坏了"。
> 电气上二者都是"输入不变"，所以检测逻辑是真的被触发了；
> 但**没有真实故障传感器**，所以不能声称"验证了传感器失效场景"。

### 3.4 类 D：真实电气输入

- 第 9 步的恢复是**人手拧电位器**造成的真实电压变化（不是喂数据）；
- 第 3 步的确认是**真实静置输入**（含电位器自身噪声 ~9 mV 峰峰）。

除这两点外，本阶段没有引入任何新的电气条件（没有短路、没有断路、没有注入噪声）。

| # | 项 | 为什么 |
|---|---|---|
| 1 | **真实传感器失效**（断线、探头坏、变送器卡死） | 手上只有电位器，没有可失效的传感器。当前证据只能说明"输入不变会被检出" |

| 5 | GUI 连真板显示故障 | 界面联动是**软件模拟**验证的；真板路径走的是脚本（同一套 `protocol.py`，但没点过界面按钮） |
| 6 | 上位机断线重连后掩码语义 | 重连后设备仍在 ACTIVE，界面不会自动收到旧状态（没有"查询当前故障"命令）。这是设计缺口，需在 7D 决定要不要加查询 |

### 一个必须说明的小缺口

现在**没有"查询当前故障"的命令**。上位机后连、或断线重连，看不到设备的既有故障状态——
只能等下一次跃变。当前靠 `stat` 文本行的 `DIAG ... mask=` 可以人工看到，但二进制侧没有对应查询。
是否补一个（例如 GET_STAT 帧尾部追加，或新命令 `0x16 GET_DIAG`）需要你定，
**本轮没做，也不擅自做**。
