## 5. 归因分析（H7/H8/H12）

### 5.1 设备侧证据：全部为零

| 计数器 | 值 | 含义 |
|---|---|---|
| `drops` | 0 | 采样环没溢出，一个采样点都没丢 |
| `adc_err` / `uart_err` / `rx_err` / `frame_err` | 0 / 0 / 0 / 0 | 设备端未记录任何错误 |
| `txd=` | **0 B** | **发送环从未满**，`app_tx_write` 一次都没丢字节 |
| `BOOT` | 0 | 中途没有复位 |
| 链路中断 | 0 | 串口没有断开重连 |

`txd=0` 是本轮最关键的证据：**固件没有丢过任何一个字节**，所有帧都完整进了发送环并被 DMA 送走。

### 5.2 主机侧证据：缺口与解析错误成对出现

- `seq8 缺口 = 45` 与 `整帧丢失 = 45` **完全相等** → 丢的是整帧，不是帧内错位。
- `解析错误 = 30`：解析器看到了**畸形字节流**，随后重新同步。
  若只是"少收若干帧"，解析错误会更少；出现 30 次说明**字节流被截断/拼接**，即主机侧丢了一块连续字节。
- 59 个打点中有 **56 个**带缺口，但每次只有 1–3 帧，分布在全小时，未集中在某一分钟。

### 5.3 两个候选原因，本轮无法定论

| 候选 | 支持证据 | 反对证据 |
|---|---|---|
| **A. 主机侧 USB/驱动缓冲溢出**（最可能） | 缺口与解析错误成对出现；`txd=0` 说明固件没丢；本机在测试期间**同时执行了大量文件读取/命令**（静态审查），进程可能被短暂调度走，CH340 驱动缓冲（KB 级）在 1744 B/s 下约 2–3 s 即溢出 | 无法直接观测驱动层丢弃计数 |
| B. 设备 UART TX 线路级异常（DMA 供数不及导致移位错误） | 也能造成主机侧解析错误 | `uart_err=0`（但那是 RX 侧计数，**不能**排除 TX 侧问题）；且 `txd=0` 说明环没满 |

**结论**：只能确定"丢失发生在设备发送环之后、上位机解析器之前"这一段。
**不排除**候选 B，但候选 A 更符合全部证据，且与"测试期间主机同时在跑大量其它任务"这一事实吻合。

> 与 2026-11-03 那轮对照：当时同样代码、同样波特率、`0 缺口 / 0 解析错误`，
> 差别在于那一轮测试期间主机**没有并发负载**。这是倾向 A 的间接证据，但不构成证明。
