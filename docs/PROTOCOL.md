# 通信协议说明（V5）

固件实现：`App/Src/app_proto.c`　上位机实现：`host/protocol.py`
两端必须逐字节一致，改任何一侧都要同步另一侧并重跑 `host/tests/`。

---

## 1. 物理层

| 项 | 值 |
|---|---|
| 接口 | USART1（PA9 = TX，PA10 = RX） |
| 波特率 | 115200 |
| 数据位 / 校验 / 停止位 | 8 / None / 1 |
| 电平 | 3.3V TTL（**不是 RS232**） |
| 接收方式 | DMA + 空闲中断（IDLE） |
| 发送方式 | DMA + 环形发送队列 |

---

## 2. 帧格式

所有多字节字段为**小端**。

```
+------+------+------+-----+-----+---------------+--------+--------+
| 0xAA | 0x55 | TYPE | LEN | SEQ | PAYLOAD[LEN]  | CRC_LO | CRC_HI |
+------+------+------+-----+-----+---------------+--------+--------+
   1B     1B     1B    1B    1B     LEN 字节         2B（小端）
```

| 字段 | 说明 |
|---|---|
| `0xAA 0x55` | 帧头。用两字节而不是一字节，是为了降低噪声被误判成帧头的概率 |
| `TYPE` | 消息类型，见第 3 节 |
| `LEN` | 载荷字节数，0 ≤ LEN ≤ 40 |
| `SEQ` | **设备全局帧序号**：所有帧（SAMPLE/EVENT/STAT/ACK/BOOT）共用一个计数器，逐帧 +1，溢出回绕。上位机用它发现"整帧丢失"；换向命令的序号与它无关 |
| `PAYLOAD` | 载荷，内容由 TYPE 决定 |
| `CRC16` | CRC-16/CCITT-FALSE，覆盖 **TYPE + LEN + SEQ + PAYLOAD**（不含帧头和 CRC 自身） |

**CRC 参数**：多项式 `0x1021`，初值 `0xFFFF`，不反射，不做最终异或。
标准校验值：`crc16(b"123456789") == 0x29B1`，两端单测都断言了这一点。

**为什么 SEQ 和 CRC 都要**：CRC 只能发现"内容被改坏"，发现不了"整帧根本没到"；
SEQ 不连续才能暴露后者。两者互补，缺一不可。

---

## 3. 消息类型

### 3.1 设备 → 上位机

| TYPE | 名称 | LEN | 周期 | 说明 |
|---|---|---|---|---|
| `0x81` | SAMPLE | 10 | 100Hz | 每个采样点一帧 |
| `0x82` | EVENT | 8 | 事件触发 | 告警级别变化 |
| `0x83` | STAT | 37 | 1Hz + 请求/改阈值/清零时 | 运行统计 |
| `0x84` | ACK | 2 | 应答触发 | 命令执行结果 |
| `0x85` | BOOT | 7 | 上电一次 | 固件与配置信息 |
| `0x86` | FAULT | 9 | 事件触发 | 故障确认 / 恢复（Stage 7C，仅诊断使能后） |

### 3.2 上位机 → 设备

| TYPE | 名称 | LEN | 说明 |
|---|---|---|---|
| `0x10` | SET_THR | 4 | 设置阈值（成功后立即回推一帧 STAT） |
| `0x11` | SET_LED | 1 | 控制 LED |
| `0x12` | GET_STAT | 0 | 请求统计帧 |
| `0x13` | RESET | 0 | 清零所有计数（清零后立即回推一帧 STAT） |
| `0x14` | PING | 0 | 心跳，仅回 ACK |
| `0x15` | SET_DIAG | 1 | 使能 / 关闭故障诊断（Stage 7C） |
| `0x16` | GET_DIAG | 0 | 请求故障状态快照（Stage 7C-2，应答见 §4.10） |

所有上位机命令都会收到一帧 ACK（`0x84`）。

## 4. 载荷定义

### 4.1 SAMPLE (0x81) — 10 字节

| 偏移 | 长度 | 字段 | 类型 | 单位/说明 |
|---|---|---|---|---|
| 0 | 4 | `t_ms` | u32 | 设备运行时间，ms |
| 4 | 2 | `raw_mv` | u16 | 原始电压，mV（未滤波） |
| 6 | 2 | `filt_mv` | u16 | 滤波后电压，mV |
| 8 | 1 | `level` | u8 | 0=NORMAL 1=WARN 2=CRIT |
| 9 | 1 | `seq8` | u8 | 采样序号低 8 位，用于查缺口 |

### 4.2 EVENT (0x82) — 8 字节

| 偏移 | 长度 | 字段 | 类型 |
|---|---|---|---|
| 0 | 4 | `t_ms` | u32 |
| 4 | 1 | `from` | u8 |
| 5 | 1 | `to` | u8 |
| 6 | 2 | `filt_mv` | u16 |

**合法迁移**：`NORMAL↔WARN`、`WARN↔CRIT`。状态机只允许相邻跳转，
所以 `NORMAL->CRIT` 这种跨级事件**不会出现**（会分两步上报）。

### 4.3 STAT (0x83) — 37 字节

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | `uptime_ms` | u32 | 运行时间 |
| 4 | `samples` | u32 | 已处理采样数 |
| 8 | `drops` | u32 | 采样环溢出丢弃数（**可观测的丢点**） |
| 12 | `adc_err` | u32 | ADC/DMA 错误 |
| 16 | `uart_err` | u32 | 串口硬件错误（ORE/FE/NE/PE） |
| 20 | `rx_err` | u32 | 接收环溢出 + 重新武装失败 |
| 24 | `frame_err` | u32 | 帧格式或 CRC 错误 |
| 28 | `changes` | u32 | 告警状态切换次数。**自上次上电或 `reset` 命令以来的累计值**，不是某个时间窗口内的次数；要做窗口统计请用首末两次 STAT 求差 |
| 32 | `thr_warn` | u16 | 当前 WARN 阈值，mV |
| 34 | `thr_crit` | u16 | 当前 CRIT 阈值，mV |
| 36 | `level` | u8 | 当前级别 |

### 4.4 ACK (0x84) — 2 字节

| 偏移 | 字段 | 值 |
|---|---|---|
| 0 | `req_type` | 被应答的命令 TYPE |
| 1 | `result` | 0=OK 1=参数错误 2=未知命令 |

> **关于帧头 SEQ**：ACK 的帧头 `SEQ` 取的是**设备全局帧序号**（与 SAMPLE/STAT 共用同一个逐帧 +1 的计数器），
> **不回显**被应答命令自身的序号。载荷里的 `req_type` 只说明"应答的是哪条命令"。
> 因此上位机做丢帧判断时，必须把 ACK 也纳入序号连续性检查，不能把它当"与序号无关"的帧跳过。

### 4.5 BOOT (0x85) — 7 字节

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | `fw_version` | u16 | 0x0500 = V5.0 |
| 2 | `sample_rate` | u16 | Hz |
| 4 | `dma_buf` | u8 | ADC DMA 缓冲长度 |
| 5 | `filter_depth` | u8 | 移动平均深度 |
| 6 | `decim` | u8 | 上报抽取比（1 = 全量） |

### 4.6 SET_THR (0x10) — 4 字节

| 偏移 | 字段 | 类型 |
|---|---|---|
| 0 | `thr_warn` | u16 |
| 2 | `thr_crit` | u16 |

约束（固件与上位机都会按 32 位算术校验）：`50 < warn 且 warn + 50 <= crit <= 3300`（保证滞回减法不下溢，且 CRIT 降级释放门槛不低于 WARN）。

### 4.7 SET_LED (0x11) — 1 字节

`0` = 灭，`1` = 亮。设过之后 LED 不再跟随告警级别，直到重新上电。

### 4.8 FAULT (0x86) — 9 字节

两种用途，**帧结构完全相同**，靠 `event` 区分：

| `event` | 用途 | 何时发 | 会重复吗 |
|---|---|---|---|
| `0` | **状态快照** | 只在收到 `GET_DIAG` 时 | 每次查询都回一帧 |
| `1` / `2` | 确认 / 恢复事件 | 状态**跃变**时自动发 | 不重复（提交成功才拉平） |

事件帧**只在跃变时发一帧**，中间不重复。设备默认不产生 1/2 事件
（诊断关闭），主机下发 `SET_DIAG` 打开后才可能出现；快照与诊断开关无关（见 §4.10）。

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | `t_ms` | u32 | 事件时刻（设备运行时间） |
| 4 | `event` | u8 | **0 = 快照，1 = 确认，2 = 恢复** |
| 5 | `fault_id` | u8 | 故障种类，见下表；`0` = 未指定单一故障（无故障，或多故障并存） |
| 6 | `active` | u8 | 上报**之后**"仍处于已确认态"的故障位掩码。**快照时它是权威值** |
| 7 | `value` | u16 | 与故障相关的观测量。`STUCK` 用最近结算块的 span（mV）；`fault_id=0` 时为 0 |

故障编号与位掩码（当前只登记了一种，其余编号会被设备忽略、不产生帧）：

| `fault_id` | 名称 | 位掩码 | 判据（摘要） |
|---|---|---|---|
| `0x01` | `STUCK` 信号卡死 | `0x01` | 连续 3 个 1 秒块内 `max−min < 50 mV` |

**为什么是掩码而不是单个 id**：多故障并存时，某一个恢复只清自己那一位，
其余位原样带出，上位机因此能看出"还有别的故障没恢复"。
例如恢复 `STUCK` 时若另有故障在报，`active` 不为 0。

**字节示例**（这三组是契约向量，`fw_tests/test_fault.c` 与 `host/tests/test_fault_joint.py` 共用）：

```
确认：AA 55 86 09 00 B8 0B 00 00 01 01 01 0C 00 F9 45
       └SEQ=0  └t=3000    ev=1 id=1 mask=1 value=12
恢复：AA 55 86 09 01 70 17 00 00 02 01 00 78 00 54 D2
       └SEQ=1  └t=6000    ev=2 id=1 mask=0 value=120
```

#### 4.8.1 上报语义与发送失败处理

设备内部有两个**必须分开**的状态：

| 名称 | 含义 | 谁维护 |
|---|---|---|
| `active` | 设备**当前真实的**故障位掩码（来自诊断模块） | 每样本更新 |
| `reported` | **已成功提交到 TX 发送队列**的故障位掩码 | 只在整帧入队成功后更新 |

> **`reported` 不等于"上位机已知"。** `app_tx_write()` 成功只说明字节进了发送环；
> DMA 是否发完、线路上有没有干扰、对端有没有收到，这一层都不知道。
> 所以 GET_DIAG 快照（§4.10）仍然是重连后重新对齐状态的必要手段，两者不能互相替代。

规则：

1. **只在 `active != reported` 时提交**。相等时直接返回，不构造帧、不取 SEQ。
2. **队列空间不足时：不消耗设备全局 SEQ、不更新 `reported`**，本周期直接放弃。
   空间判断必须在**取 SEQ 之前**（`app_task.c` 用 `app_tx_pending()` 算剩余字节，
   要求 `剩余 ≥ PROTO_MAX_FRAME` 才尝试），否则会白烧一个序号，
   上位机会把它算成"整帧丢失"。
3. **入队失败绝不写半帧**：整帧丢弃并计入 `txd=`，帧边界始终完整。
4. **失败后至少间隔 `APP_FAULT_RETRY_MIN_MS`（100 ms）才重试**，避免队列长期满时
   每 10 ms 的采样周期都去刷一次。
5. **允许合并中间边沿**：队列阻塞期间如果发生了 确认→恢复→再确认，
   设备不会补发这三条历史事件；队列恢复后**只提交当时的 `active`**
   （即"现在到底有没有故障"），上位机看到一帧与当前状态一致的确认。
   这是有意的取舍——链路中断几分钟后补发几百条历史事件对操作员没有意义，
   而"状态必须对"是硬要求，漏掉的边沿由 GET_DIAG 快照兜底。
6. **快照不参与这套状态机**：`event=0` 只读 `active`，不改 `active`/`reported`，
   不产生确认或恢复事件。

> **实时事件 vs 状态快照**：`event=1/2` 回答"刚刚发生了一次跃变"，
> `event=0` 回答"此刻还有哪些故障"。前者可能因上述合并而缺失，
> 后者永远反映当前真实状态。**快照不用于恢复历史事件**，只用来看"现在"。

### 4.9 SET_DIAG (0x15) — 1 字节

| 偏移 | 字段 | 类型 | 说明 |
|---|---|---|---|
| 0 | `enable` | u8 | `0` = 关闭诊断，`1` = 使能 |

- **只接受 `0` 和 `1`**。`LEN ≠ 1` 或 `enable > 1` 时直接回 ACK `result=1`（参数错误），
  **不会进入回调**——非法命令碰不到采样与通信路径。
- ACK 在配置**生效之后**发出，所以"收到 OK 就代表已经打开/关闭"。
- 关闭诊断**不会**清掉已上报的故障掩码：一个真实存在的故障不该因为关了诊断就"凭空恢复"。

### 4.10 GET_DIAG (0x16) — 请求 LEN=0

**用途**：让上位机随时问"你现在还有哪些故障"。解决两件事——
① 事件帧因发送环满而没提交出去，两端状态对不齐；② 断线重连后本地什么都不知道。

**请求**：`TYPE=0x16`，`LEN=0`。`LEN ≠ 0` → ACK `result=1`，不执行快照逻辑。

**应答顺序固定：先 ACK，后快照**（两帧都用设备全局帧序号，与 SAMPLE/STAT 同一计数器）：

| 帧 | 内容 |
|---|---|
| ACK `0x84` | `req_type=0x16`，`result=0` |
| FAULT `0x86` | `event=0` 的快照 |

**快照语义**（这是 §4.8 的 `event=0`，帧结构不变）：

| 情况 | `fault_id` | `active` | `value` |
|---|---|---|---|
| 无故障 | `0` | `0` | `0` |
| 恰好一个故障 | 该故障编号（如 `1`） | 掩码 | 该故障观测量 |
| 多故障并存 | `0`（不指定单一故障） | 完整掩码 | `0` |

**五条硬规则**：

1. 快照**不补发历史事件**。一次查询只回答"现在"，中间发生过几次确认/恢复看不出来。
2. 快照**不是事件**。上位机不得把它显示成一次"故障确认"或"故障恢复"。
3. `active` 是**权威值**：上位机收到快照后，应直接用 `active` 覆盖本地状态。
4. 快照**只读**：不改设备的故障状态，也不改"已提交状态"，不产生任何事件。
5. 快照在**入队那一刻**才取状态（不是收到请求时），所以它的内容不会比排在它前面的帧更旧。

**重复请求**：每个合法请求都有自己的 ACK；快照允许合并成一帧"最新状态"，
不要求一比一，也不会无限积压。

**字节示例**（契约向量，与 `fw_tests/test_fault.c`、`host/tests/test_fault_joint.py` 共用）：

```
快照(有故障)：AA 55 86 09 05 40 1F 00 00 00 01 01 19 00 11 DE
              └SEQ=5  └t=8000    ev=0 id=1 mask=1 value=25
快照(无故障)：AA 55 86 09 06 28 23 00 00 00 00 00 00 00 00 11
              └SEQ=6  └t=9000    ev=0 id=0 mask=0 value=0
请求 GET_DIAG：AA 55 16 00 07 B8 4D
              └SEQ=7（命令序号，独立于设备全局帧序号）
```

## 5. 文本调试通道
同一个串口上还保留了一套 ASCII 命令，**首字节不是 `0xAA`**，因此不会和二进制帧冲突：

```
help                 命令列表
stat                 打印统计（含 cmd/txd_B 与 DIAG 行），同时推送 STAT 帧
thr <warn> <crit>    改阈值，单位 mV
led on|off           控制 LED
diag on|off          使能 / 关闭故障诊断（与 SET_DIAG 等价）
reset                清零所有计数（同时推送 STAT 帧）
```

`stat` 会在三行内输出：

```
STAT t=...ms n=... drop=... adc=... uart=... rxf=... frm=... chg=... cmd=ok/err txd=...B
ERRSRC ore=... fe=... ne=... pe=... pto=... rxrst=ok/fail
DIAG en=... state=... conf=... span=... blk=... unev=... mask=...
```

- `ERRSRC` 是**错误分类**，只走文本通道，**二进制 STAT 帧格式不变**（仍是 37 字节）；
- `pto` = 半截帧超时复位次数（`APP_RX_FRAME_TIMEOUT_MS`）；
- `rxrst=ok/fail` = 主循环 RX 重挂守护的成功/失败次数；
- `DIAG` 是故障诊断的即时快照，同样只走文本通道：
  `state` 0=CLEAR 1=CONFIRMING 2=ACTIVE 3=RECOVERING；
  `conf` = 已确认次数累计；`span` = 最近结算块的峰峰值（mV）；
  `blk` = 当前块已累计的样本数（0 表示刚结完块）；
  `unev` = 因样本不足被跳过的块数；`mask` = 已上报的故障位掩码。

用途：没有上位机时用串口助手手敲，排查硬件问题最快。
上位机也会把这些行显示在"日志 / 文本通道"里。

### 5.1 仅调试构建才有的命令（`APP_DEBUG_INJECT = 1`）

正式版（`APP_DEBUG_INJECT = 0`）**不编入**这三个命令，键入会得到 `ERR unknown command`：

| 命令 | 作用 | 用途 |
|---|---|---|
| `adcinject` | 只置一次"ADC 错误"标志（`app_measure_on_error()`），不碰硬件 | Stage 1 恢复链路验证 |
| `oreinject` | 停接收 30 ms 攒字节制造**真实 ORE**，再重挂；返回 `saw_ore=0/1` | Stage 3 ORE 验证 |
| `rxstop` | 停掉接收且不重挂（等价于"某次重挂失败后"的状态） | Stage 3 加固 B 验证 |

> 这三个命令的存在会改变固件尺寸（Release `21208` → Debug 约 `21792`），
> **板上长期运行的一定要是 `APP_DEBUG_INJECT = 0` 的版本**。

## 6. 带宽与负载核算

| 项 | 计算 | 结果 |
|---|---|---|
| SAMPLE 帧长 | 5 + 10 + 2 | 16 B |
| 100Hz 上报 | 16 × 100 | 1600 B/s |
| 串口容量 | 115200 / 10 | 11520 B/s |
| **带宽占用** | 1600 / 11520 | **13.9%** |
| 单帧发送时间 | 16 × 10 / 115200 | 1.39 ms |
| 占采样周期 | 1.39 / 10 | 13.9%（DMA 后台完成，不占 CPU） |

结论：**带宽不是瓶颈，DMA 的作用是让发送完全不阻塞主循环**。
若将来要加更多通道，优先压缩载荷而不是提高波特率。

## 7. 错误处理与恢复

| 异常 | 设备行为 | 上位机行为 |
|---|---|---|
| 收到坏 CRC | 丢弃该帧，`frame_err++`，从下一字节重新找帧头 | 计解析错误，不显示脏数据 |
| 帧头后字节不是 0x55 | 重新同步，`frame_err++` | 同上 |
| LEN > 40 | 丢弃，重新同步 | 同上 |
| **半截帧**（收了帧头没收完，之后没字节了） | 超过 `APP_RX_FRAME_TIMEOUT_MS`（**50 ms**）无新字节 → 复位解析器，`pto++`；**`frame_err` 不变**（不是坏帧，是不完整帧） | 无感（不会产生脏数据） |
| 串口 ORE 溢出 | 错误回调清 ORE 标志、`uart_err++`、重挂接收。**实测补充**：若 DMA 正在收，取走 DR 的同时 ORE 就被清了，错误中断来不及执行，此时不计数也不影响链路 | 表现为序号缺口 → 告警 |
| 接收重新武装失败（ISR 内） | `s_rx_fail++`（计入 STAT 的 `rx_err`） | 长时间无数据 → 提示断开 |
| **接收长时间没在跑**（重挂失败 / 被 abort） | 主循环守护每轮查 `huart1.RxState`，不是 `BUSY_RX` 就重挂，**限速 200 ms**；成功打 `[rec] uart rx restarted`，失败打 `[rec] uart rx restart failed, retry in 200ms` | 同上 |
| 整帧丢失（噪声/断开） | 无法感知 | **靠 SEQ 跳变发现** |
| 上位机断开 | 继续采样，帧被丢弃（发送环满则整包丢弃并计 `tx_drop_bytes`） | 界面提示断开，数据保留，可重连 |

> 上面两条加粗的是 Stage 3 加固后新增的行为，实测数据见 `TEST_REPORT` §14.1。
> **尚未验证**：`usart_start_rx()` 真正返回 `HAL_BUSY` 时守护的表现（风险 R1）。

## 8. 兼容性

- 固件版本通过 BOOT 帧广播，上位机应在连接后先读一次，版本不符时提示。
- `LEN` 已预留余量（最大 40），新增字段可以在**尾部追加**并同时增大 LEN，
  旧上位机会因为 `LEN` 不匹配而丢弃（当前实现严格按长度校验），这是有意的：
  宁可丢帧也不解析错位数据。
