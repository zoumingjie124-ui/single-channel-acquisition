# 连续运行测试方案与记录表（1 小时 / 8 小时）

> **状态：空模板。本轮没有跑 1 h，也没有跑 8 h。**
> 表里出现的唯一一行带数字的内容，明确标了「示例」，是为了说明填写格式，**不是实测结果**。
> 跑完之后请把实际数据填进 §4，并在 §7 写结论。

---

## 1. 为什么要分两档

| 档 | 回答什么问题 | 主要风险 |
|---|---|---|
| **1 小时** | 短周期抖动、偶发丢帧、USB 链路稳定性、界面/CSV 是否拖慢采集 | 低，是 8 h 的"入场券" |
| **8 小时** | 计数溢出、长时间温漂、内存/缓冲慢性泄漏、凌晨无人时的自恢复能力 | 高，**这是"能不能交付"的分水岭** |

1 h 不过就不要跑 8 h —— 8 h 只是把同一个问题放大 8 倍，不会自己消失。

## 2. 判定门槛（先定标准，再跑）

### 2.1 硬指标（任一不满足即 FAIL）

| # | 指标 | 门槛 | 依据 |
|---|---|---|---|
| H1 | SAMPLE 频率 | **100.00 ± 0.10 Hz** | 设计 100 Hz；v5.1.1 实测 100.01 |
| H2 | STAT 频率 | **1.00 ± 0.05 Hz** | `APP_STAT_PERIOD_MS = 1000` |
| H3 | `drops`（采样环溢出） | **= 0** | 一个采样点都不能丢 |
| H4 | `frame_err` | **= 0** | 无 CRC / 格式错误 |
| H5 | `adc_err` | **= 0** | 无 ADC/DMA 错误 |
| H6 | `uart_err` | **= 0** | 无 ORE/FE/NE/PE |
| H7 | `seq8` 缺口（样本级） | **= 0** | 样本连续 |
| H8 | 整帧丢失（帧头 SEQ） | **= 0** | 帧连续 |
| H9 | BOOT 帧数量 | **= 0（除首帧）** | 中途复位会立刻暴露 |
| H10 | 链路中断次数 | **= 0** | USB 掉线/重枚举 |
| H11 | 设备 uptime 与实际时长的偏差 | **< 0.1%** | 证明 1 ms 时基没漂 |
| H12 | 解析错误（上位机侧） | **= 0** | 两端协议一致 |

### 2.2 观察指标（不判 FAIL，但必须记录并解释）

| # | 指标 | 期望 | 偏离时说明什么 |
|---|---|---|---|
| O1 | `changes` 首末增量 | **0**（输入不动） | 非 0 说明信号漂移或干扰触发了告警；需记录发生时刻 |
| O2 | 单段 SAMPLE 数波动 | ±1% 内 | 超出说明 PC 侧读取被阻塞（历史原因见 `TEST_REPORT` §8.1） |
| O3 | 板子/环境温度 | 手记 | 温漂是 8 h 最可能的隐性变量 |
| O4 | PC 侧进程内存 | 无持续增长 | 缓慢增长 = 上位机有泄漏 |
| O5 | 电压读数均值 | 与开跑时相差 < 5 mV | 偏大说明参考或输入在漂 |

## 5. 字段从哪来、怎么算

| 字段 | 来源 | 算法 |
|---|---|---|
| 墙钟 | 手记或日志每 60 s 打点的 `[ Ns]` | — |
| 设备 `uptime_ms` | STAT 帧偏移 0（`uptime_ms`） | 直接抄 |
| SAMPLE 累计 | `soak.py` 每行的 `SAMPLE n(+m)` 中 `n` | 末 − 首 |
| 本段频率 | — | **本段帧数 ÷ 本段实际秒数**（用设备 uptime 差，不用墙钟，避免 PC 侧卡顿污染） |
| STAT 累计 | 同上的 `STAT` 列 | 末 − 首，再 ÷ 时长 |
| drops / frame_err / adc_err / uart_err | STAT 帧偏移 8 / 24 / 12 / 16 | 末 − 首 |
| seq8 缺口 | `soak.py` 累计列 | 末 − 首 |
| 整帧丢失 | 同上（用帧头 SEQ，不是载荷） | 末 − 首 |
| BOOT 帧数 | `soak.py` 末尾"BOOT 帧" | 应为 0（首帧不计） |
| 链路中断 | `soak.py` 末尾"链路中断次数" | 应为 0 |
| `changes` | STAT 帧偏移 28 | 末 − 首 |
| 解析错误 | `soak.py` 末尾 | 应为 0 |

**为什么用设备 uptime 算频率而不是墙钟**：PC 侧一次 GC 或系统卡顿就能让墙钟多出几百毫秒，
7 小时的窗口里这些误差会累积。设备 uptime 来自 TIM2（HSE 8 MHz × PLL），是这轮测试里最可信的时基。

## 6. 异常处理预案

| 现象 | 处置 | 记录方式 |
|---|---|---|
| `soak.py` 报"链路中断"并自动重连 | **不要停**，让它自己重连（脚本会在 30 s 内重试） | 记 `链路中断次数`+1，并在表 B 备注写明时刻 |
| 重连成功但序号重新对齐 | 正常行为（脚本会重置期望值） | 备注写"重连后已对齐，缺口不累计" |
| BOOT 帧出现 | 设备复位了 → **本轮作废**，查原因（看门狗/掉电/USB 供电不足） | 在 §7 写"作废 + 原因" |
| `drops` 开始增长 | 主循环被拖慢 → **FAIL**，立即停，保留日志 | — |
| `frame_err` 开始增长 | 线路/波特率问题 → **FAIL**，检查接线与共地 | — |
| 板子发烫 / 电流异常 | **立即断电**，按电气安全优先 | 记录现象 |
| PC 睡眠导致串口断开 | 重跑；先把电源计划改成"从不睡眠" | — |
