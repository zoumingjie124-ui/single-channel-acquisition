## 1. Stage 8 总体目标

把"软件层已验证"和"板级已验证"之间的**最后一段空档**补上，只做三件事：

1. **补证据**：让已经写好但只在 PC 上跑过的机制（TX 满载重试、诊断长跑）拿到真实板级证据；
2. **划边界**：明确哪些故障用现有电位器永远测不出来，把"不能声称"的地方写死在文档里；
3. **收口**：把 R1–R21 逐条给出"能关 / 不能关 / 关不掉的原因"，不留模糊项。

**不做**：不加故障类型、不改检测算法与阈值、不改协议帧结构、不改采样链路、不做无关重构。
Stage 8 的产出应当只有**测试记录 + 判定结论 + 风险状态更新**，不应有新功能代码。

### 1.1 证据分级口径（全文统一使用）

## 3. Stage 8A：TX 环真实满载恢复

### 3.1 代码审查结论（先给结论，再给依据）

**投递链路**（`App/Src/app_tx.c` + `app_fault.c` + `app_task.c`）：

| 环节 | 实现 | 关键数字 |
|---|---|---|
| 环形缓冲 | `s_ring[1024]`，`head`/`tail` 只在主循环改 | 容量 1024 B，留 1 空位区分满/空 → 可用 1023 B |
| 入队 | `app_tx_write()`：空间不足则**整包丢弃**并累加 `s_drop_bytes`，返回 0 | 绝不写半帧 |
| 出队 | `app_tx_poll()`：一次搬 `n ≤ 128 B` 到 `s_stage`，`s_busy=1`，启动 DMA | `APP_TX_STAGE_SIZE = 128` |
| 完成 | `app_tx_on_cplt()` / `app_tx_on_error()` 清 `s_busy` | 只有这两个入口能清 |
| FAULT 提交 | `app_fault_service()` 三道闸门：已对齐不发 → 队列无空间不发 → 100 ms 节流 | 空间判据 `free_b ≥ PROTO_MAX_FRAME(47)` |
| 帧长 | FAULT = 5+9+2 = **16 B**；SAMPLE 17 B；STAT 44 B；ACK 9 B | `PROTO_HEADER_LEN=5` |

**结论 1：普通帧会烧 SEQ，FAULT 不会。**
`emit_frame()`（SAMPLE/STAT/EVENT/ACK/BOOT/快照）是"先取号、再入队、结果 `(void)` 丢掉"，
所以**环满时普通帧会被丢弃并留下一个 SEQ 空洞**——这正是上位机"整帧丢失"检测的工作方式，属设计内行为。
而 `fault_emit()` 走的是 `app_fault_service()` 的闸门②，**在取号之前**判断空间，所以正常情况下不会烧 FAULT 的号。

**结论 2：闸门②与真正写入之间没有并发生产者。**
`app_cmd_poll()`（步骤 1）在主循环**先于**该块执行，`process_sample()` 的 SAMPLE 也在步骤 2；
块内只有 `service()` 与快照两次 `app_tx_write`，二者用"留 47 B 余量"（16+16 < 47）保证第二次也写得进。
**ISR 不产生任何入队**（`s_busy` 只被中断写 0），所以"检查成功但写入失败"在现有结构下不会发生。
→ 与 R18 的 `CODE REVIEW PASS` 一致。

**结论 3（新发现，需要登记）：`s_busy` 没有超时兜底。**
若 TX 完成中断（`HAL_UART_TxCpltCallback`）或错误回调**丢失一次**，`s_busy` 会永久停在 1 →
`app_tx_poll()` 每次直接 return → 环不再排空 → 所有输出（SAMPLE/STAT/文本/FAULT）**永久停摆**，
且**没有任何计数器能反映这件事**（`s_drop_bytes` 只在入队失败时增长，此时环满后也不再增长）。
这是一条"静默失效"路径，且与故障诊断无关，属于**协议栈之外的可靠性缺口**。

> 本轮按约束**不修、不改 `TEST_INVENTORY`**。建议下一轮登记为 **R22：TX 完成中断丢失导致发送永久停摆（无超时、无计数）**，
> 并在 8A 的观测项里加一条"8A 结束后 `s_busy` 必须回到 0"。

### 3.2 如何安全制造真实满载（不需要改配置）

**先说不可行的三条**（写下来避免执行时走弯路）：

| 想法 | 为什么不行 |
|---|---|
| 拔掉 USB-TTL | 拔掉后 CH340 断电，但 STM32 的 USART **不检测对端是否存在**，TX 照常移位、DMA 照常完成 → 环照样排空。而且拔掉后也无法观测 |
| 让 CH340 停止接收（RTS/流控） | 当前配置**未启用硬件流控**，RTS 不起作用 |
| 降低波特率 | 属改配置，且会同时破坏上位机链路 |

**可行方案：用"命令放大"把环灌满。**
一条文本 `stat\r\n` 只有 6 B 上行，但设备回复 ≈ **254 B**（STAT 帧 44 B + `STAT` 行 ~90 B + `ERRSRC` 行 ~50 B + `DIAG` 行 ~70 B）。

| 量 | 数值 | 说明 |
|---|---|---|
| 正常下行占用 | ≈1744 B/s | SAMPLE 17 B × 100 Hz + STAT 44 B × 1 Hz（与 1 小时长跑实测 1744 B/s 吻合） |
| 链路上限 | 11520 B/s | 115200 8N1 |
| 灌命令后（每 10 ms 一条） | 100 × 254 ≈ **25.4 KB/s** | 远超 11.5 KB/s |
| 净填充速度 | ≈ 25.4 − 11.5 ≈ **13.9 KB/s** | — |
| **灌满 1023 B 所需** | **≈ 74 ms** | 设计推演值，实测以 `txd=` 增长为准 |

> 这是**设计推演，不是实测**。执行时以 `stat` 的 `txd=` 字节数开始持续增长作为"已满"的客观标志。

**副作用（必须预告，不是失败）**：灌满期间 SAMPLE 帧会被丢弃 → 上位机看到 **SEQ 跳号 / 整帧丢失增长**，
这是设计内行为；`drops`（设备端 ADC 环溢出）必须仍为 0，两者不是一回事。

**方案 B（备用，需批准且证据更弱）**：把 `APP_TX_RING_SIZE` 临时改 256 再重烧。
但它测的是"256 B 环"而不是"1024 B 环"，且改配置属改固件。
**上一轮 `HW_VERIFY_NEXT.md` H1 曾建议改 64 / 256，本方案 A 的结论是"不需要改"——
那条建议被本文件取代，但本轮按约束**未修改** `HW_VERIFY_NEXT.md`，执行时以本文件为准。**

### 3.3 执行步骤（零固件改动）

前置：板子在线（端口先查，见 `README.md` §5.1）、PA1 接电位器、烧的是正式版 `Code=22468`。

| 步 | 动作 | 观察点 |
|---|---|---|
| 0 | 发 `reset` 清零计数，`stat` 记录基线 | `drops/adc/uart/frm/txd` 全 0 |
| 1 | `SET_DIAG 1`，保持电位器不动 | 约 3 s 后 1 帧 FAULT `event=1 active=1`；`stat` 的 `DIAG` 行 `mask=1 rep=1` |
| 2 | 开始灌 `stat\r\n`（每 10 ms 一条，持续 4 s），同时用脚本抓 FAULT 帧 | `txd=` 开始增长 = 环已满；此阶段应**收不到任何 FAULT 帧** |
| 3 | **在灌命令的同时**缓慢来回拧电位器 3 s（制造"恢复"边沿） | 设备内部 `active` 应变为 0，但因环满 `reported` 停在 1 |
| 4 | 停止灌命令，静置 1 s | 恢复后应收到**恰好 1 帧** FAULT `event=2 active=0` |
| 5 | `stat` 核对 | `mask=0 rep=0`（拉平）；`txd=` 停止增长 |
| 6 | 保持静止 3 s | 收到 1 帧 `event=1 active=1`（重新卡死），`mask=1 rep=1` |
| 7 | 可选（调试器）：暂停内核读 `s_ctx.fault` | `commit_cnt` 增量 = 观测到的 FAULT 帧数；`retry_fail` 见判定表 |

**工具**：`host/tools/diag_watch.py`（抓 FAULT）+ 一个**临时**灌命令脚本。
> ⚠ 灌命令脚本目前不存在，而本轮不允许新增代码文件。
> 执行时的替代方案（零新增文件）：直接用 `python -c` 内联（一次性命令，不入库），
> 或由你批准新增 `host/tools/txflood.py`。**建议后者**（可复现、可留存），但需你点头。

### 3.4 记录要求

- 原始抓帧日志 `docs/STAGE8A_TX_FULL_RAW.txt`（脚本自动落盘，**不许手抄**）；
- 灌命令的时间窗、命令条数、`txd=` 起止值；
- 每次 `stat` 的原文（含 `DIAG ... mask= rep=`）；
- 若用调试器，记录暂停时刻的 `active/reported/commit_cnt/retry_fail/s_busy`。

### 3.5 通过标准（全部满足才算 PASS）

| # | 判据 | 期望 | 依据 |
|---|---|---|---|
| A-1 | 灌满期间收到的 FAULT 帧数 | **0** | 环满则发不出 |
| A-2 | 恢复后提交的 FAULT 帧数 | **恰好 1**，`event=2 active=0` | 状态差驱动，只提交最新 `active` |
| A-3 | 提交延迟 | 停灌后 **≤ 200 ms** | 100 ms 节流 + 主循环周期 |
| A-4 | `rep` 追上 `mask` | 停灌后 **≤ 1 s** | 同上 |
| A-5 | 采集未受影响 | `drops=0`、`adc_err=0`、`uart_err=0` | 拥塞不得反噬采集 |
| A-6 | 重新卡死 | 静置 3 s 后 1 帧 `event=1`，`mask=rep=1` | 可重复触发 |
| A-7 | 结束后 `s_busy`（若可读） | **= 0** | 排除 §3.1 结论 3 的停摆 |
| A-8 | （可选）`retry_fail` | 增量 **0** | 闸门②在取号前生效的直接证据 |

### 3.6 失败判定

| 现象 | 判定 | 说明 |
|---|---|---|
| 恢复后 0 帧 FAULT，且 `rep` 一直 0 而 `mask` 为 1 | **FAIL：事件永久丢失** | 状态差模型失效 |
| 恢复后同一状态收到 ≥2 帧 | **FAIL：重复上报** | 拉平逻辑失效 |
| 灌满期间收到 FAULT 帧但 `rep` 未前进 | **FAIL：状态不一致** | — |
| 停灌 2 s 后 `rep` 仍未拉平 | **FAIL：重试未生效** | — |
| `retry_fail` 增量 > 0 | **FAIL（设计缺陷）**：闸门被绕过，SEQ 已白烧 | 说明检查与写入之间出现了生产者 |
| `drops > 0` 或 `uart_err > 0` | **FAIL：拥塞反噬采集** | — |
| 灌满期间 SAMPLE 出现 SEQ 跳号 | **PASS（预期）**，不计失败 | 但必须与"整帧丢失"计数一起记录 |

### 3.7 风险与安全

| 风险 | 处理 |
|---|---|
| 灌命令导致接收环（256 B）溢出 | 每 10 ms 仅 6 B 上行（600 B/s），远离溢出；若 `rxf` 增长则降低灌速 |
| 长时间环满导致 TX 停摆不可恢复（§3.1 结论 3） | 单次灌满 **≤ 5 s**，结束后必须确认输出恢复（收到 SAMPLE/`stat` 有回应） |
| 电位器来回拧动误触发 WARN/CRIT | 拧动幅度控制在 NORMAL 区（< 2400 mV） |
| **电气安全** | 全程只用跳线与电位器，**不触碰 3.3V 与 GND 短接**；PA1 保持 0~3.3 V |

## 4. Stage 8B：诊断长期运行（1 h / 8 h）

### 4.1 目标

证明"**诊断使能态**"下长时间运行不扰动采集、不误报、不慢性失效。
（7B 的 10 分钟长跑是**默认关闭态**，不能代表使能态。）

### 4.2 前置条件（缺一不可）

1. **关闭睡眠 / 休眠 / USB 选择性暂停**——命令见 `SOAK_PLAN.md` §9.1，**测完必须还原**（§9.2）。
   原因：睡眠会让进程挂起、数据丢在 USB 层，而设备 `drops` 仍为 0 → 假干净（`TEST_REPORT` §17.3）。
2. `soak.py` 与 GUI / `diag_watch.py` **不能同时占同一个串口**。
3. 输入保持**不会自行跳变**的状态（电位器固定、无人碰线）。
4. 端口先查（CH340 会换号，见 `README.md` §5.1）。

### 4.3 步骤

**1 h（先做）**

| 步 | 动作 |
|---|---|
| 1 | 关睡眠 → 确认（`powercfg -q ... STANDBYIDLE` 显示 0） |
| 2 | `reset` 清零；`stat` 记基线 |
| 3 | `SET_DIAG 1`；等第一帧确认 FAULT；`stat` 确认 `mask=1 rep=1` |
| 4 | 跑 `soak.py 60 <端口>`（60 分钟），后台 |
| 5 | 每 5 min 由另一进程… **不可行（同口冲突）**——改为：每 5 min 手动中断？ |

> **工具缺口（必须如实说明）**：`soak.py` 全程独占串口，**不统计 FAULT 帧**，也不允许别人同时打点。
> 因此 1 h / 8 h 的"FAULT 帧数"与"5 分钟打点"**在不改工具的前提下拿不到**。
> 三个可选做法，全部需要你批准其中之一：
>
> | 方案 | 做法 | 代价 |
> |---|---|---|
> | B1（推荐） | 给 `soak.py` 加 FAULT 计数 + 每 5 min 输出一行 `DIAG` 快照请求（复用现有协议，无固件改动） | 改 Python 工具（**需批准**） |
> | B2 | 长跑只跑 `soak.py`（拿到采样率/错误计数），FAULT 心跳另起一段 `diag_watch.py 600` 单独测 10 min | 分段，长跑期间拿不到故障指标 |
> | B3 | 手工：每 30 min 用串口助手打断/重连打 `stat` | 打断长跑，证据有断点，**不推荐** |

**8 h（1 h 通过后）**：同流程，`soak.py 480 <端口>`，每 30 min 打点（需 B1）。

| 环境 | 室温（±3 ℃ 记录即可，不要求恒温） | 人工 |

### 4.5 通过标准

沿用 `SOAK_PLAN.md` 的 **H1–H12**（100.00±0.10 Hz、`drops=0`、`BOOT=0`、时基偏差 <0.1% 等），另加：

| # | 判据（诊断相关） | 期望 |
|---|---|---|
| B-1 | 固定输入下的 FAULT 帧总数 | **恰好 1 帧确认**（不应随运行时间增长） |
| B-2 | `conf` 增量 | **0**（输入不动就不该有新确认） |
| B-3 | `rep` 与 `mask` | 全程相等（无拥塞必须拉平） |
| B-4 | `span` 观测值 | 稳定在静置噪声量级（实测 8–12 mV），不出现异常大值 |
| B-5 | `state` | 恒为 `2`（ACTIVE），不出现 CLEAR/RECOVERING 抖动 |

### 4.6 失败判定

| 现象 | 判定 |
|---|---|
| FAULT 帧数随小时数线性增长 | **FAIL：疑似每样本重发或重复确认** |
| `conf` 增长而输入未动 | **FAIL：误报**（需对比 `span` 判断是否接触噪声） |
| `rep ≠ mask` 持续 > 2 s | **FAIL：提交链路停滞** |
| 任一门槛（H1–H12）失败 | **FAIL**，按 `SOAK_PLAN` 中止预案处理 |

### 4.7 风险

| 风险 | 处理 |
|---|---|
| 8 h 期间误触电位器/碰线 → 假边沿 | 电位器固定 + 桌面不碰；有边沿就在记录里标注时刻，不删数据 |
| 睡眠未真正关闭 | 开跑前后各查一次 `powercfg`；`uptime` 偏差 > 0.1% 即视为窗口被污染，重跑 |
| 8 h 过夜断电/U 盘休眠 | 输出重定向到本地磁盘（不是 U 盘）；先做一次 5 min 试跑确认落盘 |
| 长跑期间诊断误报掩盖真实问题 | 固定输入下若出现边沿，优先怀疑接触噪声（R12），不当成"诊断已验证" |

### 5.2 哪些能用现有硬件验证 / 哪些必须买

| 故障场景 | 现有硬件能做吗 | 怎么做 | 证据强度 |
|---|---|---|---|
| **输入卡死在某个电平**（电位器固定） | ✅ 能 | 静置 3 s | 板级，但**只能说明"输入恒定"**，≠ 传感器失效 |
| **短接到 GND** | ✅ 能 | 跳线 PA1→GND，观察 `raw_mv≈0` | 板级真实电气 |
| **短接到 3.3V 轨** | ✅ 能 | 跳线 PA1→3.3V（**这是合法输入电压，不是短路电源**） | 板级真实电气；但**与"合法满量程"电气上不可区分** |
| **超量程（>3.3 V）** | ❌ 不能 | F1 的 ADC 过驱会钳位在 4095，**信息已丢失**；加 5 V 会损伤 ADC | 物理不可达 |
| **输入断线** | ⚠ 只能观察 | PA1 悬空无上下拉，读数不确定 → **没有可判据的特征值** | 观察实验，不构成"断线检测已验证" |
| **探头失效（漂移/间歇/周期性抖动）** | ❌ 不能 | 需要真实传感器 | — |
| **4–20 mA 断线（电流环开路）** | ❌ 不能 | 需要变送器 + 采样电阻 | — |

### 5.3 安全规程（先读再动手）

1. **断电改线**：任何接线变更先断电（拔 USB 或断 3.3V），不许热插拔。
2. **PA1 只允许 0~3.3 V**，禁止负压、禁止 5 V。
3. **绝对禁止 3.3V 与 GND 直接短接**（会拉垮 LDO/USB）。
4. **USB 供电与 ST-Link 3.3V 只接一路**。
5. 短接实验用**跳线帽**而不是手持表笔（手抖会碰到相邻脚）。
6. 每次改线后先看 `raw_mv` 是否在预期范围，再看诊断输出。

### 5.4 执行步骤

**C-1 短接 GND（现有硬件，10 分钟）**

| 步 | 动作 | 期望 |
|---|---|---|
| 1 | 断电，PA1 改接 GND，上电 | `raw_mv` ≈ 0（板级零点基线 +1.75 mV 量级） |
| 2 | `SET_DIAG 1`，静置 5 s | 收到 1 帧确认，`value` = 块内峰峰值（应很小） |
| 3 | 断电改回电位器 | — |

> **这一项的真正价值**：它证明"贴 0 电平会被判成卡死"——即 **STUCK 对"恒定输入"敏感，但对"是哪种故障"不敏感**。
> 这正是 §5.5 要写的边界。

**C-2 短接 3.3V 轨（现有硬件，10 分钟）**：同上，`raw_mv` 应 ≈ 3299 mV，且**会同时触发 WARN→CRIT 告警**（与诊断独立）。
> 观察点：告警状态机（电平）与诊断（行为）**互不影响**，两条链路各走各的。

**C-3 悬空观察（现有硬件，5 分钟，不改代码）**

| 步 | 动作 | 记录 |
|---|---|---|
| 1 | 断电，拔掉 PA1 的线，上电 | — |
| 2 | 连续采 30 s 原始 `raw_mv` | min / max / 均值 / 标准差、是否贴 0 或 4095、是否有大幅度跳变 |
| 3 | 结论 | **只记录现象**，据此判断"断线是否具备可判据特征"；**不得声称断线检测已验证** |

**C-4 真实传感器（需采购/接入）**：偏差测试 10 min + 真卡死测试 + 恢复测试；判据见 §5.6。

### 5.5 STUCK 诊断的适用边界（必须写进交付）

| 边界 | 说明 |
|---|---|
| 只对"**块内极差**"敏感 | 连续 3 个 1 s 块 `max−min < 50 mV` 才确认。**输入恒定 = 触发**，不管是"传感器坏了"还是"工艺真的稳" |
| **不区分故障种类** | 短 GND、短 3.3V、传感器卡死、正常稳态，只要电平不动都可能被判卡死 |
| 对"**慢漂移**"不敏感 | 每秒漂 > 50 mV 的缓慢失效不会被判卡死（属变化率类故障，本阶段未实现） |
| 对"**周期性抖动**"不敏感 | 传感器输出在 ±100 mV 周期抖动，块内极差大 → 不触发 |
| `STUCK_DELTA_MV=50 mV` **仍是待确定值** | 依据只有电位器静置实测峰峰 8–12 mV；真实传感器必须重新标定 |
| 断线**测不了** | 无上下拉，悬空读数不确定 |

### 5.6 C-4 通过标准（接真实传感器后）

| # | 判据 | 期望 |
|---|---|---|
| C-1 | 正常波动 10 min | FAULT 确认帧 **0**（这才是 `STUCK_DELTA_MV` 是否合适的唯一判据） |
| C-2 | 真卡死（输出被固定） | **3 s 内**确认，`value` = 实测块内峰峰值 |
| C-3 | 恢复 | 连续 2 个干净块后 1 帧恢复 |
| C-4 | 重复 | 再卡死能再次确认（`conf` 累加） |

### 5.7 风险

| 风险 | 处理 |
|---|---|
| 短接 3.3V 轨时误碰 GND | 用跳线帽、单手操作、改线前断电 |
| 悬空观察时静电/干扰损坏 ADC | 观察期间不加任何外部电压；只读不写 |
| 用"电位器固定"冒充"传感器失效" | **禁止**。报告里必须写"输入恒定"，不能写"传感器故障" |

## 7. 其他遗留项目

### 7.1 R1：真实 HAL 重挂失败（`usart_start_rx()` 返回 BUSY）

**结论：Stage 8 仍无法主动制造，保持 CODE REVIEW 级别。**

| 尝试路径 | 可行性 |
|---|---|
| 让 `RxState` 停在 BUSY_RX 再调 `ReceiveToIdle_DMA` | 守护函数内部已有二次检查会挡住，等于要绕过自己的保护 |
| 用调试器改 `huart->RxState` 寄存器再触发 | 属**改运行状态**而非测试固件，可作为"实验"但证据性质仍是"注入"，不是"真实失败" |
| 拔插/干扰自然触发 | 不可控、不可复现 |

**建议**：不追求关闭 R1，改为**明确记为"设计假设未验证"**，并在代码注释里写明该分支的预期行为。若你要求关闭，需要接受"调试器注入"这一弱化证据，并单独标注。

### 7.2 R2：绝对电压精度

- 需要**万用表**（状态待确认）。步骤已在 `docs/CALIB_ABSOLUTE.md`（P0 GND / P1 3.3V 轨 / P2 分压中点）。
- **必须同时记录 VDDA 实际值**：固件把 3300 mV 写死，若 VDDA 实为 3.28 V，
  "满量程 3299.87 mV"恰恰说明误差被参考假设吸收，而不是 ADC 准确。
- 缺仪器 → 本条在 Stage 8 内**无法关闭**。

### 7.3 R17：多故障快照

**结论：在"只有一种故障"的固件上永远关不掉。**

- 生产路径只有 `STUCK` 一个位，快照的 `fault_id=0 + active=多bit` 分支走不到；
- 唯一办法是引入第二种故障类型——**属新增功能，本阶段明确不做**；
- 因此 R17 保持 `UNIT PASS`，并注明"**待第二种故障实现后再上板**"。
- 不要为了让这条"过关"而用白盒置位冒充板级证据。

### 7.4 R18：队列检查与写入并发

- 已有 `CODE REVIEW PASS`（ACK/FAULT 均在主循环，无 ISR 入队）。
- 8A 执行时**顺带复核**：只要没有新增中断内入队，该结论继续成立。
- 若将来把入队搬进 ISR，必须改为"以 `app_tx_write()` 返回值为准拉平 `reported`"。
