## 3. Stage 8A：TX 环真实满载恢复（可选）

> **执行条件**：R2、8D、8B（1 h + 8 h）全部完成且有余力。
> **顺序**：放在 8B 之后。8A 会让 SAMPLE/STAT 等帧被丢并留下 SEQ 跳号，放最后不会污染长跑结论。
> **执行前**先发 `reset` 清零计数（对应 §3.3 步骤 0）。


### 3.1 代码审查结论（先给结论，再给依据）

**投递链路**（`App/Src/app_tx.c` + `app_fault.c` + `app_task.c`）：

| 环节 | 实现 | 关键数字 |
|---|---|---|
| 环形缓冲 | `s_ring[1024]`，`head`/`tail` 只在主循环改 | 容量 1024 B，留 1 空位区分满/空 → 可用 1023 B |
| 入队 | `app_tx_write()`：空间不足则**整包丢弃**并累加 `s_drop_bytes`，返回 0 | 绝不写半帧 |
| 出队 | `app_tx_poll()`：一次搬 `n ≤ 128 B` 到 `s_stage`，`s_busy=1`，启动 DMA | `APP_TX_STAGE_SIZE = 128` |
| 完成 | `app_tx_on_cplt()` / `app_tx_on_error()` 清 `s_busy` | 只有这两个入口能清 |
| FAULT 提交 | `app_fault_service()` 三道闸门：已对齐不发 → 队列无空间不发 → 100 ms 节流 | 空间判据 `free_b ≥ PROTO_MAX_FRAME(47)` |
| 帧长 | FAULT = 5+9+2 = **16 B**；SAMPLE 17 B；STAT 44 B；ACK 9 B | `PROTO_HEADER_LEN=5` |

**结论 1：普通帧会烧 SEQ，FAULT 不会。**
`emit_frame()`（SAMPLE/STAT/EVENT/ACK/BOOT/快照）是"先取号、再入队、结果 `(void)` 丢掉"，
所以**环满时普通帧会被丢弃并留下一个 SEQ 空洞**——这正是上位机"整帧丢失"检测的工作方式，属设计内行为。
而 `fault_emit()` 走的是 `app_fault_service()` 的闸门②，**在取号之前**判断空间，所以正常情况下不会烧 FAULT 的号。

**结论 2：闸门②与真正写入之间没有并发生产者。**
`app_cmd_poll()`（步骤 1）在主循环**先于**该块执行，`process_sample()` 的 SAMPLE 也在步骤 2；
块内只有 `service()` 与快照两次 `app_tx_write`，二者用"留 47 B 余量"（16+16 < 47）保证第二次也写得进。
**ISR 不产生任何入队**（`s_busy` 只被中断写 0），所以"检查成功但写入失败"在现有结构下不会发生。
→ 与 R18 的 `CODE REVIEW PASS` 一致。

**结论 3（代码审查备注）：`s_busy` 依赖 TxCplt / ErrorCallback 清除，缺少超时兜底。**

- `app_tx_poll()` 在 `s_busy=1` 时直接 return；`s_busy` 只由 `app_tx_on_cplt()` / `app_tx_on_error()` 清除。
- **若这两个回调丢失**，TX poll 会持续提前返回，环不再排空，所有输出（SAMPLE / STAT / 文本 / FAULT）静默停摆，且没有计数器能反映。
- 标注：**CODE REVIEW FINDING / NOT TESTED**。
- 这是读代码推演出的**设计缺口**，**不是已观测到的故障**：本项目现有测试中没有出现过回调丢失，也没有证据表明会出现。**不得描述为已发生。**
- 处理：不新增风险编号、不修改固件、不新增测试；已登记于 `TEST_INVENTORY.md` §5.2。
- 8A 若执行，仍保留"结束后 `s_busy` 回到 0（若可读）"一项（见 A-7），作为旁证，而非专项验证。

### 3.2 如何安全制造真实满载（不需要改配置）

**先说不可行的三条**（写下来避免执行时走弯路）：

| 想法 | 为什么不行 |
|---|---|
| 拔掉 USB-TTL | 拔掉后 CH340 断电，但 STM32 的 USART **不检测对端是否存在**，TX 照常移位、DMA 照常完成 → 环照样排空。而且拔掉后也无法观测 |
| 让 CH340 停止接收（RTS/流控） | 当前配置**未启用硬件流控**，RTS 不起作用 |
| 降低波特率 | 属改配置，且会同时破坏上位机链路 |

**可行方案：用"命令放大"把环灌满。**
一条文本 `stat\r\n` 只有 6 B 上行，但设备回复 ≈ **254 B**（STAT 帧 44 B + `STAT` 行 ~90 B + `ERRSRC` 行 ~50 B + `DIAG` 行 ~70 B）。

| 量 | 数值 | 说明 |
|---|---|---|
| 正常下行占用 | ≈1744 B/s | SAMPLE 17 B × 100 Hz + STAT 44 B × 1 Hz（与 1 小时长跑实测 1744 B/s 吻合） |
| 链路上限 | 11520 B/s | 115200 8N1 |
| 灌命令后（每 10 ms 一条） | 100 × 254 ≈ **25.4 KB/s** | 远超 11.5 KB/s |
| 净填充速度 | ≈ 25.4 − 11.5 ≈ **13.9 KB/s** | — |
| **灌满 1023 B 所需** | **≈ 74 ms** | 设计推演值，实测以 `txd=` 增长为准 |

> 这是**设计推演，不是实测**。执行时以 `stat` 的 `txd=` 字节数开始持续增长作为"已满"的客观标志。

**副作用（必须预告，不是失败）**：灌满期间 SAMPLE 帧会被丢弃 → 上位机看到 **SEQ 跳号 / 整帧丢失增长**，
这是设计内行为；`drops`（设备端 ADC 环溢出）必须仍为 0，两者不是一回事。

**不改 `APP_TX_RING_SIZE`**（本轮决策）。`HW_VERIFY_NEXT.md` H1 中"改环大小为 64 / 256"的建议被本方案取代；该文件本轮未修改，执行时以本文件为准。

### 3.3 执行步骤（零固件改动）

前置：板子在线（端口先查，见 `README.md` §5.1）、PA1 接电位器、烧的是正式版 `Code=22468`。

> **串口会话约束（硬性）：全程只允许“一个进程、一个串口会话”，由它同时负责发灌命令与收帧解析。**
> 串口是独占资源：`diag_watch.py`、GUI、`soak.py` **都不能与本步骤同时打开同一个口**，
> 第二个进程要么打不开，要么把前一个挤掉——两种都会让"谁在收帧"变得不可解释。
> 因此本阶段的灌命令**不能用"一边 `python -c` 灌、一边 `diag_watch.py` 抓"的两进程方式**。

| 步 | 动作 | 观察点 |
|---|---|---|
| 0 | 发 `reset` 清零计数，`stat` 记录基线 | `drops/adc/uart/frm/txd` 全 0 |
| 1 | `SET_DIAG 1`，保持电位器不动 | 约 3 s 后 1 帧 FAULT `event=1 active=1`；`stat` 的 `DIAG` 行 `mask=1 rep=1` |
| 2 | 用**同一个脚本会话**一边灌 `stat\r\n`（每 10 ms 一条，持续 4 s）一边解析收到的帧 | `txd=` 开始增长 = 环已满；此阶段应**收不到任何 FAULT 帧** |
| 3 | **在灌命令的同时**缓慢来回拧电位器 3 s（制造"恢复"边沿） | 设备内部 `active` 应变为 0，但因环满 `reported` 停在 1 |
| 4 | 停止灌命令，静置 1 s | 恢复后应收到**恰好 1 帧** FAULT `event=2 active=0` |
| 5 | `stat` 核对 | `mask=0 rep=0`（拉平）；`txd=` 停止增长 |
| 6 | 保持静止 3 s | 收到 1 帧 `event=1 active=1`（重新卡死），`mask=1 rep=1` |
| 7 | 可选（调试器）：暂停内核读 `s_ctx.fault` | `commit_cnt` 增量 = 观测到的 FAULT 帧数；`retry_fail` 见判定表 |

**工具**：

- **一个 `python -c` 会话同时完成"灌"与"收"**：循环里先发一条 `stat\r\n`、再读走已到达的字节并解析，
  自己统计收到的 FAULT 帧与 SEQ 缺口。**不要**再并行调用 `diag_watch.py`（会抢同一个串口）。
- `host/tools/diag_watch.py` 仍可用于**不需要灌命令**的场合（例如 8D 前的手工观察），但**不参与本步骤**。
- 灌命令使用**一次性 `python -c`**，不入库、**不新增脚本文件**。
- **完整命令及全部参数（端口、命令内容、间隔、条数 / 持续时间）必须原样写在 `docs/STAGE8A_TX_FULL_RAW.txt` 的开头**，保证可复现。

### 3.5 通过标准（全部满足才算 PASS）

| # | 判据 | 期望 | 依据 |
|---|---|---|---|
| A-1 | 灌满期间收到的 FAULT 帧数 | **0** | 环满则发不出 |
| A-2 | 恢复后提交的 FAULT 帧数 | **恰好 1**，`event=2 active=0` | 状态差驱动，只提交最新 `active` |
| A-3 | 提交延迟 | 停灌后 **≤ 200 ms** | 100 ms 节流 + 主循环周期 |
| A-4 | `rep` 追上 `mask` | 停灌后 **≤ 1 s** | 同上 |
| A-5 | 采集未受影响 | `drops=0`、`adc_err=0`、`uart_err=0` | 拥塞不得反噬采集 |
| A-6 | 重新卡死 | 静置 3 s 后 1 帧 `event=1`，`mask=rep=1` | 可重复触发 |
| A-7 | 结束后 `s_busy`（若可读） | **仅记录，不参与判定** | 见下方说明，单次读数不足以证明"没发生过停摆" |
| A-8 | （可选）`retry_fail` | 增量 **0** | 闸门②在取号前生效的直接证据 |
| A-9 | 灌满窗口**之外**的 SEQ 跳号 | 停灌 ≥ 1 s 后 **0 新增** | 窗口内跳号属设计行为，窗口外不应有（见 §3.6.1） |

> **A-7 的结论强度（刻意压低，不接受反驳式引用）**
>
> `s_busy` 得靠调试器暂停内核或实时变量观察才能读到，**读取动作本身会改变时序**；
> 而且"结束时读到 0"只能说明**此刻**没卡住——它**不能排除**中途丢过一次完成中断、
> 随后又被下一次回调把标志清回 0（`s_busy` 只有一个 bit，看不出历史）。
>
> 因此：A-7 **只作为旁证记录，不计入 PASS / FAIL**，**也不能用来关闭 §3.1 结论 3**。
> 该结论保持 **CODE REVIEW FINDING / NOT TESTED**（`TEST_INVENTORY` §5.2），
> 要关闭它需要的是"发送停摆检测 + 超时恢复"这类**设计变更**，不是一次读数。

### 3.6 失败判定

| 现象 | 判定 | 说明 |
|---|---|---|
| 恢复后 0 帧 FAULT，且 `rep` 一直 0 而 `mask` 为 1 | **FAIL：事件永久丢失** | 状态差模型失效 |
| 恢复后同一状态收到 ≥2 帧 | **FAIL：重复上报** | 拉平逻辑失效 |
| 灌满期间收到 FAULT 帧但 `rep` 未前进 | **FAIL：状态不一致** | — |
| 停灌 2 s 后 `rep` 仍未拉平 | **FAIL：重试未生效** | — |
| `retry_fail` 增量 > 0 | **FAIL（设计缺陷）**：闸门被绕过，SEQ 已白烧 | 说明检查与写入之间出现了生产者 |
| `drops > 0` 或 `uart_err > 0` | **FAIL：拥塞反噬采集** | — |
| 灌满窗口内出现 SEQ 跳号 | **不判失败**，按 §3.6.1 区分归因 | 帧头 SEQ 缺口数与 seq8 缺口数**分别记录** |

### 3.6.1 SEQ 跳号的区分处理（按现有设计；属设计推演，执行时以实测核对）

环满时 `emit_frame()`（SAMPLE / STAT / EVENT / ACK / BOOT）先取号、再入队、结果丢弃 → 整帧被丢，**帧头 SEQ 留下空洞**；FAULT 在取号前判断空间，**不烧号**（§3.1 结论 1）。
因此灌满窗口内出现跳号是设计内行为，**不得简单判为失败**。按下表区分：

| 现象 | 归因（推演） | 判定 |
|---|---|---|
| 窗口内 SAMPLE 的 seq8 出现缺口（同时帧头 SEQ 有缺口） | SAMPLE 帧在环满时被整帧丢弃 | 预期，记录，不判失败 |
| 窗口内帧头 SEQ 有缺口，**seq8 连续** | 被丢的是非 SAMPLE 帧（如 STAT / ACK） | 预期，记录，不判失败 |
| 窗口内收到 FAULT 帧 | 环满时不应发出 | **FAIL（A-1）** |
| 停灌 ≥ 1 s（环已排空）后仍持续新增 SEQ 跳号 | 不属于环满 | **需调查**；先排除上位机 / 串口端问题 |
| 设备 `drops` > 0 | ADC 环溢出，与 TX 环无关 | **FAIL（A-5）** |

### 3.7 风险与安全

| 风险 | 处理 |
|---|---|
| 灌命令导致接收环（256 B）溢出 | 每 10 ms 仅 6 B 上行（600 B/s），远离溢出；若 `rxf` 增长则降低灌速 |
| 长时间环满导致 TX 停摆不可恢复（§3.1 结论 3） | 单次灌满 **≤ 5 s**，结束后必须确认输出恢复（收到 SAMPLE/`stat` 有回应） |
| 电位器来回拧动误触发 WARN/CRIT | 拧动幅度控制在 NORMAL 区（< 2400 mV） |
| **电气安全** | 全程只用跳线与电位器，**不触碰 3.3V 与 GND 短接**；PA1 保持 0~3.3 V |

### 7.2 R2：绝对电压精度（必做）

需要万用表（**状态待确认**：型号 / 精度等级 / 电池）。步骤见 `docs/CALIB_ABSOLUTE.md`（P0 GND / P1 3.3V 轨 / P2 分压中点）。

**必须同时记录 VDDA 实际值**：固件把 3300 mV 写死，若 VDDA 实为 3.28 V，"满量程 3299.87 mV"恰恰说明误差被参考假设吸收，而不是 ADC 准确。

记录表（每点读数三次，写原始值，不手改）：

| 点 | 万用表读数 | 固件读数（同一时段均值） | 备注 |
|---|---|---|---|
| VDDA（或板上 3.3V 轨） | | — | 写明实际测量点 |
| P0：PA1 → GND | | | |
| P1：PA1 → 3.3V 轨 | | | 比例测量，应≈3300，不能证明绝对准确 |
| P2：1.65V 中点（分压） | | | 万用表同时测 P2 电压 |

判读（**计算，非测量**）：设万用表测得 VDDA = V_A，P2 真实电压 = V_2。

- 固件读数 ≈ V_2 / V_A × 3300：该值与固件实际读数之差 = 换算与 ADC 本身的误差；
- 固件读数与 V_2 之差 = "把 VDDA 当作 3.300 V"的假设带来的**绝对误差**。
- 两者**分开写**，不得混成一个"精度"数字。
- 容差在**测量之前**写定：建议 = 1 LSB（≈ 0.81 mV @ 3.3 V）+ 万用表读数不确定度；万用表精度待确认，容差数值待定。

关闭条件沿用 `TEST_INVENTORY.md` R2：VDDA、3.3V 轨、1.65V 点三项都实测并记录。对不上就如实记误差大小，**不得声称绝对准确**。

#### 7.2.1 VDDA 直接测量 vs 3.3V 轨代理测量（两者不能互替）

固件把参考电压写死为 3300 mV，所以"绝对精度"这个结论**完全依赖 VDDA 的真值**。测法不同，能下的结论也不同：

| 测法 | 测点 | 能证明 | 不能证明 | 能否作为 R2 的关闭依据 |
|---|---|---|---|---|
| **A. 直接测 VDDA** | MCU 的 VDDA 引脚，或与之**同网络**的测试点（板上引出的 VDDA 焊盘 / 跳线帽） | 参考电压真值 → 可把"换算误差"与"参考假设误差"分开算 | — | **可以**（测得准则成立） |
| **B. 3.3V 轨代理** | 排针 3.3V / LDO 输出 | 只说明**电源轨**的电压 | 不能证明 VDDA 与之等值：二者之间若有磁珠 / RC / 走线压降，**轨值 ≠ VDDA** | **不可以单独关闭**，只能给出误差**上界** |

- 只有**经确认 VDDA 与 3.3V 轨同网络**（0 Ω / 跳线直连且中间无滤波元件）时，B 才能**近似**当 A 用。
  依据必须写进结论（看原理图，或用万用表通断档实测导通），**不能默认"同源"**。
- 记法固定两种，不许混写：
  - A：`VDDA 实测 = ____ V（测点：____）`
  - B：`以 3.3V 轨代 VDDA = ____ V（未直接测 VDDA；同网络依据：____）`
- 误差换算（相对）：`相对误差 ≈ (V_实测参考 − 3.300) / 3.300`。
  用 B 时，这个数字里**混入了"轨 − VDDA 差值"这个未知量**，所以只能写"上界"，**不能写"精度"**。

安全：改线先断电；表笔不要同时碰相邻引脚；LQFP48 引脚间距只有 0.5 mm 级，
**不要用表笔直接探 MCU 引脚**——优先找板上引出的测试点；找不到就按 B 记录并注明"未直接测 VDDA"。
**R2 需要改 PA1 接线，不要与 8B 长跑同时进行。**

**决策（2026-11-04）：保持 `CODE REVIEW PASS`，不升级为板级验证。**

- 理由：R18 问的是"**闸门②判过空间之后、`app_tx_write()` 真正写入之前**，有没有别的生产者插进来"——
  这是一个**代码结构问题**，板级观测看不到这个窗口。8A 把环灌满也不能直接证明它。
- 8A **若执行**，最好结果也只是"未观察到反例"（`retry_fail` 增量 0 属间接旁证），
  **不得**据此把 R18 标成板级 PASS，也不得改写 `TEST_INVENTORY` 里 R18 的 `CODE REVIEW PASS` 字样。
- 结论成立的前提是"入队只在主循环"这条约束；若将来把入队搬进 ISR，
  必须改为"以 `app_tx_write()` 返回值为准拉平 `reported`"，并重新评估 R18。

### 7.5 已知限制：R19 真实传感器故障诊断 NOT TESTED

- 手上只有电位器；"卡死"在电气上等价于"输入恒定"，**不能声称验证了传感器失效**。
- 不采购真实传感器 / 信号源 / 偏置电阻（决策，2026-11-04）。
- 真实传感器失效可能不被 `STUCK` 检出（例如漂移到轨、周期性抖动）。
- 报告里必须写"输入恒定"，**不得写"传感器故障"**。

`STUCK` 诊断的适用边界（原 Stage 8C §5.5，旧编号，现迁移至此）：

| 边界 | 说明 |
|---|---|
| 只对"**块内极差**"敏感 | 连续 3 个 1 s 块 `max−min < 50 mV` 才确认。**输入恒定 = 触发**，不管是"传感器坏了"还是"工艺真的稳" |
| **不区分故障种类** | 短 GND、短 3.3V、传感器卡死、正常稳态，只要电平不动都可能被判卡死 |
| 对"**慢漂移**"不敏感 | 每秒漂 > 50 mV 的缓慢失效不会被判卡死（属变化率类故障，本阶段未实现） |
| 对"**周期性抖动**"不敏感 | 传感器输出在 ±100 mV 周期抖动，块内极差大 → 不触发 |
| `STUCK_DELTA_MV=50 mV` **仍是待确定值** | 依据只有电位器静置实测峰峰 8–12 mV；真实传感器必须重新标定 |
| 断线**测不了** | 无上下拉，悬空读数不确定 |
