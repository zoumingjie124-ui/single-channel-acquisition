## 2. 故障注入方式与边界

### 2.1 注入机制

`adcinject` 是一条**只存在于调试固件**的文本命令（`#if (APP_DEBUG_INJECT != 0u)` 包住），
作用等价于 DMA 错误中断里那一行：

```c
s_recover_req = 1u;      /* app_measure_on_error() 的核心动作 */
```

之后 `DeInit → Init → 配通道 → 校准 → Start_DMA` 全部由主循环
`app_measure_poll_recovery()` 按原有逻辑执行，**被测代码路径没有被改写**。

### 2.2 这是"路径注入"，不是电气故障

| 能证明 | 不能证明 |
|---|---|
| 恢复流程能跑通、能重复 | 真实 DMA 传输错误（TE/溢出）下的恢复行为 |
| 恢复耗时与丢样代价 | ADC 硬件损坏、时钟异常等场景 |
| 限速与标志合并逻辑 | 故障原因是"持续存在"还是"一次性" |

正常接线下无法人为制造 DMA 传输错误（短接 PA1 只会让读数变化，不产生 DMA 错误），
本项目也没有做电气注入。这条边界不因本次数据而改变。

### 2.3 三组注入的设计意图

| 组 | 次数 | 间隔 | 目的 |
|---|---:|---|---|
| A | 5 | 1.5 s | 测单次恢复耗时（间隔 >1 s，避开限速） |
| B | 5 | 200 ms（总 807 ms） | 测限速：窗口内的请求应被合并 |
| C | 10 | 2.0 s | 测丢样：用累计计数器比对运行时间 |

合计 **20 次注入**，全部记录在 §3。

## 3. 注入时刻与恢复耗时（逐条）

### 3.1 组 A：单次注入 ×5

时刻定义：

- `t_send`：脚本写入 `adcinject\r\n` 的时刻
- `t_ack`：收到文本 `OK inject` 的时刻（命令已执行）
- `t_rec`：收到 `[rec] adc restarted` 的时刻（恢复完成）
- **恢复耗时 = t_rec − t_ack**（含主循环剩余步骤 + DeInit/Init/校准/Start_DMA）

| # | 注入时刻（相对组起点） | 回执延迟 | 恢复耗时 |
|---:|---:|---:|---:|
| 1 | 0.251 s | 4.7 ms | **2.5 ms** |
| 2 | 2.013 s | 4.5 ms | **4.9 ms** |
| 3 | 3.776 s | 5.1 ms | **2.1 ms** |
| 4 | 5.540 s | 4.3 ms | **4.7 ms** |
| 5 | 7.304 s | 4.7 ms | **4.7 ms** |

```
min 2.1 ms / max 4.9 ms / 平均 3.8 ms（n=5）
```

> 回执延迟（4.3–5.1 ms）是"写入命令 → 主循环处理 → 文本经发送队列出队"的调度延迟，
> **不属于恢复成本**，所以单独列出、不计入平均值。
> 最重要的一条：**4.9 ms 的最大值仍小于一个采样周期（10 ms）**，因此恢复不会吃掉采样点。

### 3.2 组 B：1 秒内连注 5 次（限速验证）

```
注入时刻(ms) : [0, 201, 403, 605, 807]
恢复完成(ms) : [9, 1006]
恢复失败     : 无
恢复次数     : 2 / 注入 5 次
相邻恢复间隔 : 997 ms        ← APP_ADC_RECOVER_INTERVAL_MS = 1000
```

时间戳说明：

- 第 1 次注入后 **9 ms** 就完成恢复 —— 对应"首次错误立即恢复"（`s_try_started == 0` 的特例）
- 之后 4 次注入（201 / 403 / 605 / 807 ms）只把 `s_recover_req` 置 1；
  主循环在 1006 ms 才执行第二次恢复，间隔 **997 ms**，正好卡在 1 s 限速上
- 窗口内 4 个请求被合并成 1 次恢复 —— 这就是"标志 + 限速"应有的行为，**不是丢失**

### 3.3 组 C：10 次注入（2 s 间隔，逐条时刻）

```
逐条注入时刻(ms)：[0, 2002, 4003, 6005, 8005, 10006, 12008, 14010, 16010, 18013]
恢复完成次数    ：10 / 10（无失败）
```

相邻间隔 2002–2003 ms（脚本按 2.0 s 循环 + 接收开销），全部 >1 s 限速，所以每次都真实恢复。

### 3.4 恢复成败统计

| 组 | 注入 | 恢复成功 | 恢复失败 | 合并掉 |
|---|---:|---:|---:|---:|
| A | 5 | 5 | 0 | 0 |
| B | 5 | 2 | 0 | 3 |
| C | 10 | 10 | 0 | 0 |

`[rec] adc restart failed` 全程未出现（日志 `[3]` 里 `恢复失败(ms)：无`）。

## 4. 丢样核算

### 4.1 为什么不能用 `t_ms` 或 `seq8`

| 指标 | 为什么不能用 |
|---|---|
| `SAMPLE.t_ms` | 它是**主循环处理该样本的时刻**，不是 ADC 转换时刻。恢复期间没有样本被处理，也就没有"间隔变大"的记录——实测全程严格 10 ms，看不出空档 |
| `seq8` | 它统计"已处理样本"的序号。恢复期间没采到的样本**压根不产生序号**，所以缺口恒为 0，无法反映丢样 |

这两个指标都会给出"完美"的假象，是本次最需要说清的测量陷阱。

### 4.2 采用的方法：累计计数 ÷ 运行时间

```
理论样本数 = Δt_ms / 10        （TIM3 配置为 100 Hz，每 10 ms 产生 1 个样本）
实际样本数 = Δn                （STAT 帧里的 n，只在样本被处理时 +1）
丢样       = Δn − round(Δt)
```

`Δn` 与 `Δt` **同取自 STAT 帧**（同一时刻的快照），因此不受主机墙钟、串口延迟影响。

### 4.3 组 C 实测

```
之前 : t=103387 ms  n=10338  drop=0  adc_err=30
之后 : t=123568 ms  n=12356  drop=0  adc_err=40
设备时间增量 : 20181 ms
样本增量     : 2018
理论样本数   : 2018.1
差值         : +0          ← 丢样 0
drops 增量   : 0
adc_err 增量 : +10（= 注入次数）
```

**10 次恢复，丢样 0 个。**

### 4.4 全程计数器一致性核对

| 项 | 数值 | 说明 |
|---|---|---|
| 基线 `adc_err` | 20 | 本次运行前累计（预跑留下） |
| 结束后 `adc_err` | 40 | 全程 +20 = 20 次注入 |
| 实际恢复次数 | 17 | 5 + 2 + 10 |
| 差值 | **3** | 正是组 B 中被限速合并掉的 3 次请求 |
| `drop` | 0 → 0 | 采样环形缓冲从未溢出 |
| `uart_err` / `rxf` / `frm` | 全 0 | 串口侧无错误 |

三个数（20 注入 / 17 恢复 / 3 合并）互相印证，说明标志与限速逻辑按设计工作。

## 5. 恢复后 30 秒采样频率统计

### 5.1 方法

```
t0 = time.time()
持续接收 30 s，逐帧解析 SAMPLE（T_SAMPLE=0x81），每帧计 1 个样本
采样率 = 帧数 / (time.time() - t0)
```

同时检查连续性：逐帧比较 `(prev.seq8 + 1) & 0xFF == cur.seq8`，
不等即记一次缺口（用于发现整帧丢失，与固件帧头 SEQ 无关）。

### 5.2 结果

```
墙钟时长     : 30.001 s
SAMPLE 帧数  : 3001
实测采样率   : 100.031 Hz      （设计 100.000）
seq8 缺口    : 0
BOOT 帧      : 0               （中途未复位）
raw_mv       : min 1528 / mean 1531.7 / max 1546
```

### 5.3 口径说明

- **100.031 Hz 不是"超额采样"**：30.001 s 墙钟里含脚本启动/退出开销，
  且 USB 批量到达会让首末帧落点有 1 帧级抖动（1/3001 = 0.033%）。
- 采样率的权威口径是长窗口总账（`TEST_REPORT` §8：601.17 s / 60117 帧 = 100.01 Hz）；
  本次 30 s 只用于确认"恢复之后仍在正常节拍上"。
- `seq8` 缺口 0 与 `drop` 0 一致，说明恢复前后没有整帧丢失。

## 6. 「重复/无效样本」为什么只能算部分验证

已排除的情况：

- **没有多推帧**：20 次注入期间样本增量 2018，理论 2018.1，**一帧都没有多**
- **恢复后序号连续**：`seq8` 缺口 0

未排除的情况：

- **旧值顶替新值**：输入是 1531 mV 静态直流（噪声 1528–1546，峰峰 18 mV）。
  若 DMA 重启后把上一次残留的转换值又推一次，它在数值上与相邻正常样本**无法区分**。

要定案需要**动态信号**（缓慢摇电位器或输入斜坡）：那时旧值会明显落后于相邻样本，
一眼能看出来。这条留到阶段二/五补。

| 现象 | 含义 |
