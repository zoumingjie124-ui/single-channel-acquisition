## 2. 算法与状态转换

### 2.1 每样本做什么（O(1)）

```
app_diag_update(d, mv_raw, now_ms)
  ├─ d == NULL        → 返回
  ├─ enable == 0      → 返回（关闭时只有这两次判断）
  ├─ blk_started == 0 → block_restart()：用本样本开一个新块，返回
  ├─ blk_samples++；更新 blk_min / blk_max（两次比较）
  └─ now_ms - blk_start_ms >= 1000 → block_close()
```

`block_close()`：算 `span = max - min` → 记录观测值 → **清零 `blk_samples`、置 `blk_started = 0`**
→ 按 span 推进状态机。新块由**下一个样本**开启。

### 2.2 状态机

```
            偏死块                偏死块 ×3
  CLEAR ───────────────► CONFIRMING ───────────────► ACTIVE   (confirm_cnt++)
    ▲                          │                        │   │
    │                          │ 干净块                  │   │ 干净块
    │                          ▼                        ▼   ▼
    │                       CLEAR                  RECOVERING ─干净块×2─► CLEAR
    │                                                     │   ▲
    └─────────────────────────────────────────────────────┘   └─ 偏死块：回 ACTIVE
```

| 转移 | 条件 | 计数器动作 |
|---|---|---|
| CLEAR/CONFIRMING → CONFIRMING | 偏死块，且未满 3 个 | `stuck_blocks++` |
| CONFIRMING → ACTIVE | 第 3 个连续偏死块 | `stuck_blocks = 0`、`confirm_cnt++` |
| CONFIRMING → CLEAR | 任意干净块 | `stuck_blocks = 0`（确认链作废） |
| ACTIVE → RECOVERING | 第 1 个干净块 | `clean_blocks = 1` |
| RECOVERING → CLEAR | 第 2 个连续干净块 | `clean_blocks = 0` |
| RECOVERING → ACTIVE | 任意偏死块 | `clean_blocks = 0`（恢复作废） |
| ACTIVE → ACTIVE | 偏死块 | `clean_blocks = 0`，**不重新确认** |

### 2.3 触发 / 确认 / 恢复（实际实现值）

| 项 | 值 | 依据 |
|---|---|---|
| 偏死块判据 | 块内 `max − min < 50 mV` | 实测静置峰峰 11 mV、接触噪声峰峰 18 mV 的 2.8 倍；≈ 满量程 1/66 |
| 块长 | 1000 ms | 与 STAT 周期对齐，便于人工比对日志 |
| 确认 | 连续 **3** 个偏死块 = 3 s | 需求指定的 N 秒 |
| 恢复 | 连续 **2** 个干净块 = 2 s | 实测接触噪声最大单步 +38 mV，1 个块可能被毛尖清掉 |
| 最小块样本数 | 50（= 单块 100 的一半） | 低于此说明块内数据不足，span 无统计意义 |
| 默认使能 | **0（关闭）** | 稳定输入会被误判，打开前需真实传感器标定 |

### 2.4 五个边界是怎么处理的

| 边界 | 处理 |
|---|---|
| 初始化 | `app_diag_init()` 全字段归零，`enable` 置默认值 0；可重复调用，幂等 |
| 计时边界 | `(uint32_t)(now_ms - blk_start_ms) >= BLOCK_MS`，无符号相减，tick 回绕（49.7 天）不出错；`>=` 语义有专门用例（999 ms 不结账 / 1000 ms 结账） |
| 无有效样本 | 块内样本 < 50  → **不参与判定**，只 `uneval_blocks++`，不打断也不推进确认链。"没数据"不等于"没变化"（后者是采样停摆，属 7C） |
| 计数溢出 | `stuck_blocks` / `clean_blocks` 理论上限被 3/2 钳住，且自增前判 `< 0xFF`；`confirm_cnt` 为 uint32，回绕仅影响统计显示、不影响判定 |
| 故障重复触发 | 恢复时把两个计数器都清 0，所以能再次从零确认；`confirm_cnt` 持续累加，ACTIVE 期间不会重复 +1（有用例） |

**过程中修掉的 3 个真实缺陷**（都是模块自身的问题，不是测试写错）：

| # | 现象 | 根因 | 修法 |
|---|---|---|---|
| 1 | 每个块都被判"样本不足"，状态永远不动 | `block_close()` 里**先**把 `blk_samples` 清 0，**再**拿它判断是否够 50 个样本 | 先把样本数取到局部变量再清零 |
| 2 | 跨段切换后第一个块的 span 不可推演，测试反复失败 | 结块样本同时充当下一个块的"种子"，min/max 继承上一段电平 | 改为"结块样本只属于旧块，新块由下一个样本开启"，并把该行为写成用例固定下来 |
| 3 | （同 2 的连带）`block_close()` 签名带着不再使用的 `mv_raw` | 设计变更后残留 | 改签名，同步前向声明 |
